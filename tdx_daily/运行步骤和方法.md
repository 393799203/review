

## 1. 分布运行步骤

## 2. 一次运行

python run_daily.py



## 第一步：`download_g4day_daily.py`

参数等价于：`--cache-dir ...\.cache\web_daily`、`--today 2026-05-11`。

1. 连库（需 `.env` 或环境变量里的 `DB_URL`）
   - 查 `tdx.raw_stocks_daily` 的 `MAX(date)`（没有数据则按脚本里“空库”规则定起点）。
2. 决定要补哪些自然日
   - 从「库中最后交易日 + 1」一直到 `2026-05-11`（含），逐日尝试（周末/节假日往往下不到 zip，会跳过）。
3. 按天下载官网 g4day
   - URL 形如：`https://www.tdx.com.cn/products/data/data/g4day/YYYYMMDD.zip`
   - 保存到：
     `...\web_daily\vipdoc\refmhq\YYYYMMDDday.zip`
   - 解压到同一 `refmhq` 目录（得到 `.md1`、`.cod` 等）。
4. 合并成 `.day`（默认走内置 Python，不走 datatool）
   - 对 `refmhq` 里已有的、能配对的全部 `.md1`/`.cod` 做 `native_day_merge`，生成/更新：
     `...\web_daily\vipdoc\{sh|sz|bj}\lday\*.day`

------

## 第二步：`tdx_import_daily_bar.py`

你会再看到一行类似：

```
→ … tdx_import_daily_bar.py --lday-path ...\vipdoc --max-date 2026-05-11
```

它会：

1. 扫描 `vipdoc\sh\lday`、`sz\lday`、`bj\lday` 下所有 `.day`。
2. 解析二进制 K 线，只导入 `trade_date ≤ 2026-05-11` 的记录。
3. 写入 PostgreSQL `tdx.raw_stocks_daily`（`ON CONFLICT (symbol, date)` 时更新）。
